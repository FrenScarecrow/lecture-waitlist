# 补充材料

本文件保存本次 brief 过程中产生、但不属于产品范围本身、且对下游（PRD / 架构 / 计划）有价值的内容。brief 只写产品范围，课程交付与方案演进的历史沉淀在这里。

## 课程交付背景与约束

- **定位**：研究生课程《软件项目管理》4 周课程作业，3–4 人一组；交付物为能在评审机上按 README 运行的 Git 仓库。真实可用是动机，但本期不上线服务器。
- **评分标准（重在判断，不在配置）**：决策日志 25 分 + 两个实验 15 分 + 可追溯性 20 分 + 代码 20 分（已列项合计 80 分，另有 20 分待确认）。实验 B 按讲义所述可能取消、待确认，不围绕它设计。
- **技术栈**：无硬性要求。
- **部署与规模**：单机部署；真实规模每场几十到几百人；管理员为不懂运维的学生助教。

## 已否决 / 演进的方案

- **候补进入方式**：由「满员自动进入候补」改为「满员提示 + 用户主动选择加入」（类 12306）；不加入不参与补位，扩容不自动补入。
- **补位确认**：曾出现「候补确认与超时顺延」故事，最终改为「直接最终补入 + 站内通知仅告知」，候补者可在讲座开始前 T 分钟前主动退出。
- **通知通道**：邮件 / 短信 / 微信全部否决；通知仅站内（补位事务提交后生成站内消息，未读标记），不配置 SMTP、不依赖外部服务。
- **补位时延指标**：由「取消后 ≤ 5 分钟」收紧为「取消事务提交即完成补位，P95 ≤ 1 秒」。
