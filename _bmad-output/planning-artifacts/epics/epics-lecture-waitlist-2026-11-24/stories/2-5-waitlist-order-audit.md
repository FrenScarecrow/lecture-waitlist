# Story 2.5：候补顺序审计

**作为** 管理员（助教），
**我希望** 任意时点的候补顺序都能据日志追溯还原，
**以便** 补位顺序事后能说清楚、公平可查证。

## 验收标准

1. 给定一场讲座，能据 `audit_log` 还原任一时刻的候补顺序与顺序号（FR-11）。
2. 每次补位/退出/清空都有对应日志条目，含操作人、时间、顺序号（`seq`）、`cohort`、`sort_ts`、结果（FR-11，ADR-004）。
3. 候补的加入时间、顺序号、补位/退出/清空记录全程留痕（FR-11）。
4. 审计行与业务变更写在同一事务内（规则 10）。
5. 缩容移入候补者的排序键（`cohort='front'`、`sort_ts = first_entered_at`）在审计中可还原，不依赖已删除的候补行（ADR-007，规则 13）。
6. 顺序号还原口径与业务排序一致：`ORDER BY CASE cohort WHEN 'front' THEN 0 ELSE 1 END, sort_ts`（规则 12）。
