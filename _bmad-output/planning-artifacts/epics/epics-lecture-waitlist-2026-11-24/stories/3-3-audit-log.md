# Story 3.3：关键操作日志

**作为** 管理员（助教），
**我希望** 查看所有关键操作的日志，
**以便** 还原补位顺序与容量调整历史、对补位纠纷有据可查。

## 验收标准

1. 每类关键操作（发布讲座、报名、取消、补位、加入/退出候补、容量调整、候补自动清空）均产生日志条目，含操作人、时间、讲座、动作、前后状态/顺序（FR-14）。
2. 管理员可查看日志，据此还原补位顺序与容量调整历史（FR-14）。
3. 日志条目与业务变更写在同一事务内（规则 10）。
4. `audit_log` 为 append-only，历史唯一来源，硬删除后靠日志还原（ADR-004）。
5. 学生访问日志查看接口返回 403（`FORBIDDEN`）（FR-2，规则 14）。
6. 补位顺序可追溯：补位日志的 `seq`/`cohort`/`sort_ts` 与候补队列一致（支撑 NFR-2「可审计」）。
